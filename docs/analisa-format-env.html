Bisakah .env project memakai model seperti docs/.env?

docs/.env adalah file .env Laravel dari project kantor "KM Online". Project booking ini memakai Node.js (Express + Sequelize) dan React (Vite), yang membaca nama variabel dan lokasi file yang berbeda.

1. Jawaban singkat

BisaFormat penulisanSintaks KEY=VALUE, komentar #, dan tanda kutip sama persis.
TidakLokasi fileBackend hanya membaca backend/.env, frontend hanya membaca frontend/.env. File di docs/ tidak pernah dibaca.
Tidak, tanpa ubah kodeNama variabelBackend butuh DATABASE_URL dan JWT_ACCESS_SECRET. Gaya Laravel DB_HOST, DB_DATABASE, dll. diabaikan, server langsung berhenti.
Bisa, dengan ubah kecilGaya DB_HOST terpisahDua file config bisa diubah agar menerima DB_HOST/DB_PORT/... sebagai alternatif DATABASE_URL. Lihat bagian 4.

2. Kenapa lokasi docs/.env tidak terbaca

Artinya file di docs/ tidak berpengaruh apa pun ke aplikasi. Menyimpannya di sana hanya menambah risiko (bagian 5).

Apa yang terjadi bila isi docs/.env disalin mentah ke backend/.env

Invalid environment variables: {

Pesan ini datang dari validasi Zod di src/config/env.js. Server berhenti sebelum menyala. Ini disengaja, supaya kesalahan konfigurasi ketahuan di awal.

4. Pilihan: mendukung gaya DB_HOST terpisah

Bila Anda lebih suka gaya Laravel karena lebih mudah dibaca, backend bisa diubah agar menerima salah satu dari dua cara: DATABASE_URL, atau lima variabel terpisah. Ada dua file yang perlu diubah: src/config/env.js (untuk server) dan src/config/database.js (untuk sequelize-cli saat migrate dan seed).

// src/config/env.js — gambaran perubahan
// Build DATABASE_URL from DB_* parts when it is not set directly
if (!process.env.DATABASE_URL && process.env.DB_HOST) {
  const { DB_USERNAME, DB_PASSWORD, DB_HOST, DB_PORT = '5432', DB_DATABASE } = process.env;
  process.env.DATABASE_URL =
    `postgresql://${encodeURIComponent(DB_USERNAME)}:${encodeURIComponent(DB_PASSWORD)}@${DB_HOST}:${DB_PORT}/${DB_DATABASE}`;
}

encodeURIComponent penting. Password yang mengandung @, :, /, atau # akan merusak URL bila tidak di-encode. Itu juga kesalahan yang paling sering terjadi saat menulis DATABASE_URL secara manual.

# Cara A (sekarang): satu URL
NODE_ENV=development
PORT=5000
DATABASE_URL=postgresql://postgres:PASSWORD@localhost:5432/booking_db
DB_SSL=false
# Cara B (setelah diubah): gaya Laravel
NODE_ENV=development
PORT=5000
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=booking_db
DB_USERNAME=postgres
DB_PASSWORD=PASSWORD
DB_SSL=false

Rekomendasi: tetap pakai Cara A. Penyedia hosting (Neon, Supabase, Railway, Render) memberikan connection string dalam bentuk satu URL, sehingga bisa langsung ditempel saat deploy. Cara B hanya soal kenyamanan, dan menambah kode yang harus Anda jelaskan ke mentor.

5. Risiko keamanan file docs/.env

File ini berisi kredensial asli, bukan contoh
  • Password database lokal, database dev kantor, dan Greenplum kantor, ditambah alamat IP server internal.
  • Satu blok komentar berisi koneksi postgres ke IP VPS Anda. Port 5432 VPS sempat terbuka ke publik sebelum UFW diaktifkan.
  • APP_KEY dan JWT_SECRET aplikasi KM Online.
PertanyaanJawaban
Ikut ter-commit ke GitHub?Tidak, selama .gitignore root tetap berisi .env. Pola tanpa garis miring berlaku di semua subfolder, termasuk docs/.env. Cek setelah git init dengan git check-ignore -v docs/.env.
Masih berisiko?Ya. Folder docs/ adalah folder yang akan Anda bagikan (laporan, artifact), dan folder project ini disinkronkan ke OneDrive. Satu salah zip atau salah upload dan kredensial kantor ikut keluar.
Sama dengan fin-pro/.env.local?Isinya mirip tetapi tidak identik. Dua-duanya file project kantor dan sama-sama sebaiknya dipindahkan.

Langkah yang disarankan

  1. Pindahkan docs/.env dan .env.local ke folder project KM Online, atau ke folder di luar fin-pro/.
  2. Bila password postgres di VPS sama dengan yang tertulis di file itu, ganti password tersebut. Port 5432 VPS sempat terbuka ke publik.
  3. Untuk project booking, gunakan backend/.env.example sebagai satu-satunya model. File ini aman di-commit karena hanya berisi nilai contoh.
