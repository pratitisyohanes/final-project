Mengisi repo GitHub yang masih kosong

Langkah dari folder fin-pro di laptop sampai semua kode tampil di GitHub, tanpa ikut mengunggah satu pun file .env.

0Fetch, pull, atau push?

Repo Anda di GitHub masih kosong: belum ada branch dan commit. Tidak ada yang bisa di-fetch atau di-pull. Arah kerjanya justru sebaliknya: kode di laptop dikirim ke GitHub dengan push. Di halaman GitHub pada gambar Anda, ini adalah bagian "…or create a new repository on the command line", karena folder fin-pro belum menjadi repo git.

PerintahArahKapan dipakai
git pushlaptop → GitHubSekarang, dan setiap selesai commit
git fetchGitHub → laptop (hanya unduh, tidak mengubah file)Nanti, bila ada perubahan di GitHub (misalnya edit README lewat web)
git pullGitHub → laptop (unduh + gabungkan)Sama seperti fetch, sekaligus menggabungkan perubahan ke file Anda

Jangan klik "creating a new file" atau menambah README lewat web sebelum push pertama. Kalau itu dilakukan, repo jadi tidak kosong dan push pertama akan ditolak (lihat bagian 7).

6Hubungkan ke GitHub dan push

Laptop, PowerShell
git remote add origin https://github.com/pratitisyohanes/final-project.git
git remote -v         # cek: origin menunjuk ke repo Anda (fetch dan push)

git push -u origin main
  • origin adalah nama panggilan untuk alamat repo GitHub.
  • -u mengingat pasangan main ↔ origin/main, jadi push berikutnya cukup git push.
  • Push pertama membuka jendela Git Credential Manager. Pilih Sign in with your browser, login GitHub, lalu izinkan. Login ini disimpan, jadi tidak perlu diulang.
Titik cek 6
  • Refresh halaman GitHub: folder backend, frontend, docs, deploy, rules, .github muncul.
  • Cari di GitHub (tekan t di halaman repo, ketik .env): hanya dua .env.example yang muncul.
Bila ternyata ada file .env yang ikut ter-push

Menghapus file di commit berikutnya tidak cukup, karena file itu tetap tersimpan di riwayat git. Ganti semua password dan secret di file itu, lalu bersihkan riwayat atau buat ulang repo. Kabari saya bila ini terjadi.

7Setelah push: Actions, fetch, dan kerja harian

GitHub Actions langsung berjalan

Push ke main menjalankan .github/workflows/deploy.yml. Job Backend tests dan Frontend build akan hijau (test tidak butuh database). Job Deploy to VPS akan merah sampai 5 secret diisi di Settings → Secrets and variables → Actions: VPS_HOST, VPS_USER, VPS_SSH_KEY, VPS_PORT, APP_URL. Merah ini tidak merusak apa pun. Panduan secret ada di rules/vps/lanjutan-swap-domain-github.md bagian 7.

Kerja harian

Laptop, PowerShell
git status                         # apa yang berubah
git add .
git commit -m "fix: deskripsi singkat perubahan"
git push

Kapan butuh fetch / pull

Laptop, PowerShell
git fetch origin                   # lihat apakah GitHub punya commit baru
git status                         # "Your branch is behind 'origin/main' by 1 commit"
git pull --rebase origin main      # ambil dan taruh commit lokal Anda di atasnya

Ini perlu bila Anda mengedit file langsung di web GitHub, atau bila muncul error ! [rejected] main -> main (fetch first) saat push. Error itu berarti GitHub punya commit yang belum ada di laptop.
