Migrasi ORM: Prisma ke Sequelize

Catatan lengkap perpindahan lapisan database backend dari Prisma ke Sequelize: apa yang dihapus, ditambah, dan diubah, bagaimana MVC, ERD, pipeline, dan data flow terpengaruh, serta bukti bahwa perilaku API tetap sama.

1. Ringkasan

Backend sebelumnya memakai Prisma 6. Sekarang memakai Sequelize 6 dengan sequelize-cli untuk migration dan seeder. Guideline tidak mewajibkan ORM tertentu. Alasan pindah: Sequelize lebih umum diajarkan di bootcamp Node.js, sehingga lebih mudah didiskusikan dengan mentor.

2. Langkah migrasi step by step

  1. Ganti dependency

    npm uninstall prisma @prisma/client
npm install sequelize pg pg-hstore sequelize-cli

    pg adalah driver PostgreSQL, pg-hstore dibutuhkan Sequelize untuk tipe hstore, dan sequelize-cli menjalankan migration dan seeder. CLI dipasang sebagai dependency biasa (bukan dev) agar Docker bisa menjalankan migration di production.

  2. Hapus file Prisma

    Folder prisma/ (schema, migration SQL, seed), src/config/prisma.js, dan src/utils/sanitizeUser.js dihapus.

  3. Konfigurasi Sequelize CLI

    .sequelizerc memberi tahu CLI lokasi config, models, migrations, dan seeders. src/config/database.js membaca DATABASE_URL dari .env lewat use_env_variable.

  4. Tulis 8 model + index

    Setiap tabel menjadi satu file di src/models/. Opsi underscored: true membuat atribut camelCase di kode dipetakan ke kolom snake_case di database. Relasi didefinisikan di fungsi associate(), lalu models/index.js memuat semua model dan menjalankan relasinya.

  5. Tulis 8 migration

    Urutan file mengikuti dependensi foreign key: users → refresh_tokens → categories → services → schedules → bookings → payments → booking_status_logs. Setiap migration punya up (buat tabel + index) dan down (hapus tabel + tipe enum).

  6. Pindahkan seeder

    Data demo sama dengan sebelumnya. Reset memakai TRUNCATE … RESTART IDENTITY CASCADE, sehingga seeder bisa dijalankan berulang kali.

  7. Sesuaikan utilitas

    pagination.js: skip/take menjadi offset/limit, dan sort menjadi format [['field', 'DESC']]. dateRange.js: filter memakai operator Op.gte/Op.lte/Op.lt. File baru compact.js membuang nilai undefined, karena Sequelize menolak undefined di where (Prisma mengabaikannya).

  8. Tulis ulang 8 service

    Logika bisnis sama. Yang berubah hanya sintaks query: findMany → findAll/findAndCountAll, contains → Op.iLike, $transaction → sequelize.transaction, $queryRaw → sequelize.query dengan replacements.

  9. Error handler & server

    Kode error Prisma (P2002, P2025, P2003) diganti class error Sequelize (UniqueConstraintError, ForeignKeyConstraintError, ValidationError). server.js memakai sequelize.authenticate() dan sequelize.close().

  10. Docker, env, README, test

    Dockerfile tidak lagi butuh OpenSSL dan prisma generate. .env dan .env.example kehilangan akhiran ?schema=public (khusus Prisma), dan .env.example mendapat DB_SSL untuk database hosting. Unit test pagination dan dateRange disesuaikan, ditambah test compact.

  11. Verifikasi

    Migration dijalankan naik, turun, lalu naik lagi. Seeder dijalankan, server dinyalakan, dan skrip end-to-end yang sama dengan versi Prisma (plus 6 skenario baru) dijalankan. Satu bug ditemukan dan diperbaiki (lihat bagian 11).

5. Perbandingan kode sebelum dan sesudah

Model

Prisma: schema.prisma
model Service {
  id              Int      @id @default(autoincrement())
  categoryId      Int      @map("category_id")
  name            String   @db.VarChar(150)
  price           Decimal  @db.Decimal(12, 2)
  durationMinutes Int      @map("duration_minutes")
  status          ServiceStatus @default(ACTIVE)
  deletedAt       DateTime? @map("deleted_at")
  category Category @relation(fields: [categoryId], references: [id])
  @@map("services")
}
Sequelize: models/service.js
const Service = sequelize.define('Service', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  categoryId: { type: DataTypes.INTEGER, allowNull: false },
  name: { type: DataTypes.STRING(150), allowNull: false },
  price: { type: DataTypes.DECIMAL(12, 2), allowNull: false },
  durationMinutes: { type: DataTypes.INTEGER, allowNull: false },
  status: { type: DataTypes.ENUM('ACTIVE', 'INACTIVE'), defaultValue: 'ACTIVE' },
}, { tableName: 'services', underscored: true, paranoid: true });

Service.associate = (models) => {
  Service.belongsTo(models.Category, { foreignKey: 'categoryId', as: 'category' });
};

Migration

Prisma: otomatis
npx prisma migrate dev --name init
# Prisma membaca schema dan menulis
# migration.sql sendiri
Sequelize: ditulis manual
async up(queryInterface, Sequelize) {
  await queryInterface.createTable('services', {
    id: { type: Sequelize.INTEGER, primaryKey: true, autoIncrement: true },
    category_id: { type: Sequelize.INTEGER, allowNull: false,
      references: { model: 'categories', key: 'id' }, onDelete: 'RESTRICT' },
    ...
    deleted_at: { type: Sequelize.DATE },
  });
  await queryInterface.addIndex('services', ['category_id']);
}

Query dengan filter, search, dan pagination

Prisma
prisma.service.findMany({
  where: {
    deletedAt: null,
    status: 'ACTIVE',
    OR: [{ name: { contains: q, mode: 'insensitive' } }],
  },
  include: { category: true },
  skip, take,
  orderBy: { price: 'asc' },
});
Sequelize
Service.findAndCountAll({
  where: {
    status: 'ACTIVE',
    [Op.or]: [{ name: { [Op.iLike]: `%${q}%` } }],
  },                          // deleted_at otomatis (paranoid)
  include: [{ model: Category, as: 'category' }],
  offset, limit,
  order: [['price', 'ASC']],
});

Transaksi booking dengan row lock

Prisma
prisma.$transaction(async (tx) => {
  await tx.$queryRaw`SELECT id FROM schedules
    WHERE id = ${scheduleId} FOR UPDATE`;
  const slot = await tx.schedule.findUnique({
    where: { id: scheduleId }, include: { service: true } });
  ...
  await tx.booking.create({ data: {
    ...,
    payment: { create: { amount } },
    logs: { create: { toStatus: 'PENDING' } },
  }});
});
Sequelize
sequelize.transaction(async (transaction) => {
  const slot = await Schedule.findByPk(scheduleId,
    { transaction, lock: transaction.LOCK.UPDATE });
  const service = await Service.findByPk(slot.serviceId, { transaction });
  ...
  await Booking.create({
    ...,
    payment: { amount },
    logs: [{ toStatus: 'PENDING' }],
  }, { include: [Payment, BookingStatusLog], transaction });
});

Prisma

8. Pipeline

Request pipeline

Tidak berubah: helmet → cors → JSON → morgan → rate limit → route → authenticate → authorize → validate → controller → service → model → database, dengan semua error berakhir di errorHandler.

Pipeline transaksi booking (versi Sequelize)

sequenceDiagram
  participant C as Controller
  participant S as bookings.service
  participant M as Sequelize Models
  participant DB as PostgreSQL
  C->>S: createBooking(userId, {scheduleId})
  S->>M: sequelize.transaction(async t => ...)
  M->>DB: BEGIN
  S->>M: Schedule.findByPk(id, {transaction: t, lock: t.LOCK.UPDATE})
  M->>DB: SELECT ... FROM schedules WHERE id=$1 FOR UPDATE
  Note over DB: request lain untuk slot yang sama MENUNGGU
  S->>M: Service.findByPk + Booking.findOne (cek bentrok)
  alt melanggar aturan
    S-->>M: throw ApiError
    M->>DB: ROLLBACK (otomatis)
  else valid
    S->>M: Booking.create({..., payment, logs}, {include, transaction: t})
    M->>DB: INSERT bookings, payments, booking_status_logs
    S->>M: slot.update({bookedCount, status}, {transaction: t})
    M->>DB: UPDATE schedules
    M->>DB: COMMIT (otomatis)
  end

Pada managed transaction Sequelize, error yang dilempar di dalam callback otomatis memicu ROLLBACK, dan callback yang selesai normal otomatis COMMIT.

13. Hal yang perlu diingat saat mengembangkan dengan Sequelize

AturanKenapa
Setiap query di dalam transaksi wajib diberi { transaction }Query tanpa opsi itu berjalan di luar transaksi, sehingga row lock dan rollback tidak melindunginya.
Gunakan compact() untuk filter opsionalSequelize melempar error bila where berisi undefined.
findAndCountAll + include → tambahkan distinct: trueTanpa itu, total bisa terhitung ganda karena join.
Include Service di riwayat → paranoid: falseAgar booking lama tetap menampilkan layanan yang sudah di-soft delete.
Login memakai User.scope('withPassword')defaultScope membuang passwordHash, sehingga tanpa scope ini bcrypt tidak bisa membandingkan password.
Ubah model = tulis migration baruModel hanya memberi tahu kode bentuk tabel, sedangkan migration yang benar-benar mengubah database.
Filter include ditulis dengan nama kolomwhere: { date: { [Op.gte]: x } }, bukan where: { [Op.gte]: x } (bug yang ditemukan di bagian 11).
Pahami sebelum Checkpoint 1Mentor kemungkinan akan bertanya soal models/index.js (cara model dimuat dan relasi dipasang), satu file migration, serta createBooking di bookings.service.js (transaksi dan LOCK.UPDATE). Coba tambahkan satu kolom baru sendiri, misalnya services.max_per_day, lewat migration addColumn sebagai latihan.
