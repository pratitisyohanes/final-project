2. Langkah pengerjaan step by step

Urutan ini juga bisa dipakai untuk menjelaskan proses development saat presentasi.

  1. Inisialisasi project

    Membuat folder backend/, package.json (CommonJS), lalu memasang dependency: express, @prisma/client, prisma, zod, jsonwebtoken, bcryptjs, helmet, cors, morgan, express-rate-limit, swagger-ui-express, dotenv. Dev dependency: jest, supertest, nodemon.

    mkdir backend && cd backend
npm init -y
npm install express @prisma/client prisma zod jsonwebtoken bcryptjs helmet cors morgan express-rate-limit swagger-ui-express dotenv
npm install -D jest supertest nodemon

  2. Konfigurasi environment

    .env.example berisi semua variabel. src/config/env.js memvalidasi variabel dengan Zod saat start: jika DATABASE_URL atau secret JWT kosong, server langsung berhenti dengan pesan jelas.

  3. Desain database dengan Prisma

    Menulis prisma/schema.prisma: 6 enum dan 8 model, lengkap dengan relasi, index, dan unique constraint. Nama kolom di database memakai snake_case (@map), sedangkan di kode camelCase.

    npx prisma validate
npx prisma migrate dev --name init     # membuat prisma/migrations/..._init/migration.sql

  4. Utilitas bersama

    Membuat ApiError, asyncHandler, helper response, pagination, sort whitelist, helper waktu WIB (overlap, generate slot), date range (today/this_week/this_month), JWT, booking code, CSV, dan skema Zod umum.

  5. Middleware

    authenticate (wajib token), optionalAuthenticate (untuk endpoint publik yang menampilkan data berbeda bagi admin), authorize(...roles), validate(schema), rate limiter, notFound, dan errorHandler global.

  6. Modul Auth

    Register, login, refresh token dengan rotasi (token lama langsung tidak berlaku), logout (mencabut refresh token), lihat dan ubah profil. Refresh token disimpan di DB dalam bentuk hash SHA-256.

  7. Modul CRUD master data

    categories (slug otomatis, tidak bisa dihapus bila masih dipakai), services (search, filter kategori/status/harga, soft delete), dan users (admin mengelola pelanggan, menonaktifkan akun sekaligus mencabut semua sesi).

  8. Modul Schedules

    Membuat slot satu per satu atau bulk generate untuk rentang tanggal. endTime dihitung dari durasi layanan. Slot yang bentrok atau sudah lewat ditolak (atau dilewati saat bulk). Status FULL/AVAILABLE dihitung otomatis dari kuota.

  9. Modul Bookings & Payments

    Booking dibuat di dalam transaksi dengan SELECT … FOR UPDATE. State machine status, pembatalan dengan batas 2 jam, pengembalian kuota slot, refund otomatis bila sudah dibayar, audit log setiap perubahan status, dan pencatatan pembayaran oleh admin.

  10. Modul Reports

    Ringkasan dashboard, layanan terlaris (Prisma groupBy), jadwal paling ramai (raw SQL EXTRACT(ISODOW …)), pendapatan per hari/bulan, dan export CSV.

  11. Wiring aplikasi & dokumentasi

    routes/index.js menggabungkan modul di /api/v1. app.js memasang helmet, cors, JSON parser, logger, Swagger UI, rate limiter, 404, dan error handler. server.js mengecek koneksi DB sebelum menerima request dan menangani shutdown dengan rapi.

  12. Seeder, Docker, test

    prisma/seed.js membuat 1 admin, 2 pelanggan, 4 kategori, 6 layanan, slot 7 hari ke belakang sampai 14 hari ke depan, dan 11 contoh booking. Dockerfile dan docker-compose.yml menyediakan Postgres + API. Test Jest menguji utilitas dan pipeline middleware.

  13. Verifikasi

    Migration dijalankan ke PostgreSQL 17 sementara, seeder dijalankan, server dinyalakan, lalu 41 skenario end-to-end diuji lewat HTTP (lihat bagian 12).

6. Arsitektur MVC

Backend ini adalah REST API, jadi tidak ada template HTML. Pola MVC diterapkan seperti berikut, ditambah lapisan Service agar controller tetap tipis:

Model

prisma/schema.prisma mendefinisikan struktur data dan relasi. Prisma Client yang di-generate (prisma.booking, prisma.schedule, …) adalah objek model yang dipakai di service.

View

Representasi JSON. Semua response dibentuk oleh utils/response.js (sukses) dan errorHandler.js (gagal) dengan format seragam. sanitizeUser dan include/select Prisma menentukan field yang tampil. Swagger UI adalah "view" dokumentasinya.

Controller

*.controller.js menerima req, memanggil service, dan mengirim view lewat success(). Controller tidak berisi query maupun aturan bisnis.

Service (business logic)

*.service.js berisi aturan bisnis: cek kuota, bentrok jadwal, transaksi, state machine. Service tidak mengenal req/res, sehingga mudah diuji dan dipakai ulang.

Routes + Schema

*.routes.js memetakan URL ke controller dan memasang middleware. *.schema.js mendefinisikan bentuk input yang valid.

13. Langkah berikutnya

Isi password database AndaPostgreSQL lokal Anda (port 5432) menolak login postgres dengan password default, jadi belum ada tabel yang dibuat di sana. Ubah DATABASE_URL di backend/.env, lalu jalankan npm run db:migrate dan npm run db:seed.
Pahami kodenya sebelum checkpointGuideline memberi nilai 0 bila pengerjaan terdeteksi 100% memakai AI, dan mentor akan menanyakan kode saat Checkpoint 1. Bagian yang paling mungkin ditanyakan: bookings.service.js (transaksi dan row lock), schedules.service.js (rumus overlap), authenticate.js/authorize.js, dan errorHandler.js. Coba ubah atau tambah fitur kecil sendiri agar Anda benar-benar menguasainya.
  • Git: folder project belum menjadi repository git. Jalankan git init di fin-pro/ dan commit secara bertahap per modul agar riwayat pengerjaan terlihat.
  • Postman: impor http://localhost:5000/api/docs.json ke Postman untuk mendapat koleksi siap pakai, lalu ekspor ke docs/.
  • Frontend: React + Vite di folder frontend/ sesuai bagian 9 dokumen perancangan. Set CORS_ORIGIN ke URL frontend.
  • Opsional: caching Redis untuk /services dan /reports, upload gambar layanan, export PDF.
  • ORM: backend sudah dipindah ke Sequelize. Lihat migrasi-prisma-ke-sequelize.html.
