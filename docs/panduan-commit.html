Langkah commit

Jalankan di terminal VS Code, dari folder fin-pro. Lingkaran berwarna menandai langkah yang membuat commit.

  1. Lihat daftar perubahan

    Pastikan kamu ada di branch main dan daftar filenya masuk akal.

    git branch --show-current
git status --short

  2. Pastikan file rahasia diabaikan

    Perintah ini harus menampilkan lima baris, satu untuk tiap file. Kalau ada yang tidak muncul, berhenti dulu dan jangan lanjut.

    git check-ignore -v .env.local docs/.env backend/.env backend/.env.backup frontend/.env

  3. Commit 1: backend

    git add memilih file yang masuk commit. git diff --cached --stat menampilkan pilihan itu supaya bisa dicek. git commit menyimpannya.

    git add backend/src backend/tests backend/scripts backend/package.json backend/package-lock.json backend/.env.example
git diff --cached --stat
git commit -m "feat(backend): add SSO login, MFA and internal API"

  4. Commit 2: frontend

    Git otomatis melewati frontend/.env dan frontend/dist/ karena keduanya ada di .gitignore.

    git add frontend
git diff --cached --stat
git commit -m "feat(frontend): add SSO login, MFA step and POS link"

  5. Commit 3: deploy

    Isinya blokir route internal di Nginx dan VITE_POS_URL di workflow. Kalau SSO mau aktif di production, tambahkan dulu VITE_SSO_URL dan VITE_SSO_CLIENT_ID ke langkah build di deploy.yml. Tanpa keduanya, production tetap memakai form email dan password.

    git add .github deploy
git diff --cached --stat
git commit -m "chore(deploy): block internal routes and set POS url"

  6. Commit 4: database dan dokumentasi

    Kerjakan setelah peringatan di atas selesai. booking_db.sql hanya berisi data demo, dan password demonya memang sudah ada di repo.

    git add backend/sql docs
git diff --cached --stat
git commit -m "docs: add database dump and update project log"

  7. Periksa hasilnya

    git status harus bersih, dan git log menampilkan empat commit baru di atas 2944cb2.

    git status
git log --oneline -5

Sebelum menjalankan git push

Push ke main langsung menjalankan deploy.yml: tes, build, upload ke VPS, migrasi database production, lalu restart backend. Dua migrasi baru akan mengubah tabel payments dan users di server.

  • GitHub Secrets. Log masih mencatat lima secret belum diisi: VPS_HOST, VPS_USER, VPS_PORT, VPS_SSH_KEY, APP_URL. Cek di GitHub, Settings, Secrets and variables, Actions. Kalau belum ada, job deploy gagal dan aplikasi di server tetap versi lama.
  • Backup database. Buat backup dulu karena migrasi langsung mengenai data production.
  • .env di VPS. Tidak ada variabel wajib baru, jadi backend tetap menyala dalam mode login lokal. Isi INTERNAL_API_KEY kalau integrasi POS dipakai, karena tanpa itu route internal menjawab 503.
git push origin main

Pantau hasilnya di tab Actions pada repo GitHub.

Nginx tidak ikut ter-deploy otomatis

Workflow hanya mengunggah folder backend dan frontend. Salin isi deploy/nginx/booking.pratitis.net.conf ke konfigurasi Nginx di VPS, lalu jalankan perintah berikut. Sebelum itu, /api/v1/internal/ masih bisa dijangkau dari internet, meski tetap dilindungi X-Internal-Key.

sudo nginx -t
sudo systemctl reload nginx
