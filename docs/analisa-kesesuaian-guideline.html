5. Pola MVC di backend

Backend memakai MVC yang dipecah lebih rapi. Model mewakili tabel, Controller menerima request dan mengirim response, dan View pada REST API adalah JSON yang dikirim balik (tampilan visualnya ada di React). Di antara controller dan model ada Service yang memegang aturan bisnis, supaya controller tetap tipis.

RouteMemetakan URL + method ke controller, memasang middlewaremodules/services/services.routes.js
Middlewareauthenticate → authorize → validate (Zod), dijalankan berurutanmiddlewares/*.js
ControllerAmbil req.params/query/body, panggil service, kirim responsemodules/services/services.controller.js
ServiceAturan bisnis, transaksi, query ke model, lempar ApiErrormodules/services/services.service.js
ModelDefinisi tabel, tipe kolom, relasi Sequelizemodels/service.js
View (JSON)Format response seragam { success, message, data, meta }utils/response.js
Error handlerUbah semua error (Zod, Sequelize, ApiError) jadi JSON dengan status yang benarmiddlewares/errorHandler.js

Contoh: perjalanan POST /api/v1/services

  1. app.js memasang helmet, CORS, express.json(), lalu rate limiter apiLimiter untuk /api/v1.
  2. routes/index.js meneruskan /services ke services.routes.js.
  3. Route: router.post('/', adminOnly, validate(createServiceSchema), controller.createService).
  4. authenticate membaca header Authorization: Bearer <token>, memverifikasi JWT, lalu mengisi req.user = { id, role }. Tanpa token → 401.
  5. authorize('ADMIN') menolak role selain ADMIN → 403.
  6. validate memeriksa body: nama minimal 3 huruf, harga > 0, durasi 15–480 menit. Gagal → 422 dengan daftar field yang salah.
  7. Controller memanggil servicesService.createService(req.body).
  8. Service memastikan kategori ada (404 bila tidak), lalu Service.create(data) lewat model.
  9. Controller membalas 201 { success: true, message: "Service created", data }.
  10. Bila ada error di langkah mana pun, asyncHandler meneruskannya ke errorHandler.
// modules/services/services.controller.js: controller hanya meneruskan dan membalas
const createService = asyncHandler(async (req, res) => {
  const data = await servicesService.createService(req.body);
  success(res, { statusCode: 201, message: 'Service created', data });
});

Integrasi API dan refresh token

  1. Saat aplikasi dibuka, useSessionBootstrap memakai refresh token tersimpan untuk mendapat access token baru.
  2. Setiap request lewat instance api; interceptor request menambahkan header Authorization: Bearer ....
  3. Bila backend membalas 401 (access token habis setelah 15 menit), interceptor response memanggil /auth/refresh sekali, lalu mengulang request yang gagal.
  4. Beberapa request 401 bersamaan berbagi satu panggilan refresh (refreshPromise), karena backend merotasi refresh token dan token lama langsung tidak berlaku.
  5. Bila refresh gagal, sesi dibersihkan dan ProtectedRoute mengarahkan ke /login.

11. Cara menjalankan project

Urutan selalu: database → backend → frontend

Butuh Node.js 20+, npm, dan PostgreSQL 16/17 yang berjalan (Windows: services.msc → postgresql-x64-17 harus Running). Perintah di bawah bisa dijalankan dari terminal VS Code (PowerShell atau Git Bash).

A. Backend (terminal 1)

# 1. Masuk folder dan install library (sekali saja)
cd backend
npm install

# 2. File .env sudah ada dan berisi password PostgreSQL Anda. Jangan ditimpa.
#    Bila perlu membuat ulang: cp .env.example .env lalu isi DATABASE_URL dan JWT secret

# 3. Buat database (lewati bila muncul "already exists")
createdb -U postgres booking_db

# 4. Buat 8 tabel
npm run db:migrate

# 5. Isi data contoh (mengosongkan semua tabel dulu!)
npm run db:seed

# 6. Jalankan server dengan auto restart
npm run dev

Bila berhasil, terminal menampilkan API running on http://localhost:5000. Cek di browser:

  1. Buka http://localhost:5173, masuk ke Services, pilih layanan dan slot.
  2. Login sebagai pelanggan budi@example.com / User12345, lakukan booking, cek di My Bookings.
